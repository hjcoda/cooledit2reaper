# Cool Edit `.ses` → REAPER `.rpp` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert legacy Cool Edit Pro `.ses` multitrack sessions into equivalent REAPER `.rpp` projects.

**Architecture:** A single stdlib-only Python script walks the `COOLNESS` binary container, decodes tracks/clips/media/tempo/EQ, and emits REAPER's text `.rpp` format directly. Unit tests use synthetic `.ses` bytes; an integration check converts the three real sessions in `/home/user/Music` and renders each generated project with REAPER.

**Tech Stack:** Python 3.14, `unittest`, no third-party packages; REAPER CLI for validation.

**Spec:** `docs/superpowers/specs/2026-11-24-ses-to-rpp-design.md`

## Global Constraints

- Python 3.8+ standard library only; no pytest, no external packages.
- One script: `cool-reap/ses2rpp.py`. Tests may import it.
- Never modify the input `.ses`.
- Default output is `<stem>.rpp` beside the input `.ses`.
- Missing media stays as an offline item with a `warning:` on stderr; `--strict` exits 1.
- Unsupported active features produce warnings, never silent data loss.
- Commit only files under `cool-reap/`; the parent repo has unrelated changes.

## Review Focus

- Non-`COOLNESS`, truncated, or unknown-layout input must print one clean error and exit non-zero, not traceback.
- A missing media file must not abort conversion (unless `--strict`) or drop the clip.
- CEP2 96-byte vs Audition 152-byte track records must be detected correctly; a wrong choice corrupts names/levels.
- Empty sessions, zero clips, zero-length clips, and clips with `sourceIn=0` must emit valid RPP without NaN/Inf.
- Windows paths with spaces/quotes/backslashes must be quoted correctly in `FILE`.

### Task 2: Decode tracks, clips, tempo, cues, loops, clip gain

**Files:**
- Modify: `cool-reap/ses2rpp.py`
- Create: `cool-reap/tests/test_decode.py`

**Interfaces:**
- Dataclasses: `Track(index:int, name:str, left:float, right:float, mute:bool, solo:bool)`, `Clip(index:int, track:int, start:int, length:int, handle:int, source_in:int, path:str|None, name:str, gain:float)`.
- `decode_tracks(chunks) -> list[Track]` — detects 96-byte CEP2 and 152-byte Audition layouts; the latter uses volume +4, mute +20, name +24.
- `gains_to_volpan(left: float, right: float) -> tuple[float, float]` — 0 dB-law balance.
- `decode_clips(chunks, media) -> list[Clip]` — 88-byte records at body+8.
- `decode_tempo(chunks) -> tuple[float, int, int]` — default `(120.0, 4, 4)`.
- `decode_cues(chunks) -> list[tuple[int, int, str]]`.
- `decode_loops(chunks, clips) -> dict[int, dict]` — `{clip_index: {"extent": int}}`.
- `decode_clip_gain(chunks, clips) -> dict[int, dict]` — static value and/or points from `ep20`; empty when identity.
